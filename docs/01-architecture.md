# 01 — معماری و قراردادهای فنی

## 1. هدف سامانه

سامانه یک وب‌اپلیکیشن PHP/MySQL برای ثبت، پایش، جستجو و گزارش‌گیری تجهیزات دانشگاه است. چهار نوع تجهیز به‌صورت منطقی از هم تفکیک شده‌اند:

- computer — کامپیوتر
- printer — چاپگر
- display — نمایشگر
- scanner — اسکنر

تمام تجهیزات در جدول پایه `assets` نگهداری می‌شوند و تفاوت نوع تجهیز با `asset_type` مشخص می‌شود. مشخصات فنی متغیر در `assets.technical` و اجزای ساختاری کامپیوتر در جداول مستقل ذخیره می‌شوند.

## 2. ساختار لایه‌ای

### public/

Document Root وب‌سرور باید روی این پوشه باشد. صفحات PHP درخواست‌های HTTP را دریافت و به سرویس‌ها و DB متصل می‌کنند.

### app/

کد مشترک برنامه:

- bootstrap و توابع زیرساختی
- سرویس Active Directory
- CSV importer
- منطق مشترک امنیت، session، CSRF، audit و دسترسی

### database/

منبع ساختار DB و migrationها.

### config/

تنظیمات runtime. `config/config.php` می‌تواند مقادیر DB را از environment بخواند.

### storage/uploads/

فایل‌های CSV منبع خصوصی هستند و نباید مستقیماً از URL وب قابل دریافت باشند.

### bin/

ابزارهای CLI مانند ساخت/به‌روزرسانی مدیر.

## 3. قرارداد ورود

`public/*.php` قبل از عملیات محافظت‌شده باید bootstrap را load کند. bootstrap:

1. config را می‌خواند.
2. timezone را تنظیم می‌کند.
3. session را فعال می‌کند.
4. headerهای امنیتی را می‌گذارد.
5. PDO را می‌سازد.
6. توابع auth/CSRF/permission/audit را ارائه می‌کند.

## 4. قرارداد asset

شناسه اصلی تجهیز `asset_no` است و باید دقیقاً ۷ رقم باشد.

نمونه معتبر:

`1234567`

نمونه نامعتبر:

- `123456`
- `12345678`
- `A123456`

شماره اموال در سطح کل سامانه unique است، نه فقط در یک نوع تجهیز.

## 5. جریان داده کلی

CSV → CsvImporter → normalized record → فرم مرحله‌ای → session wizard → کنترل تکراری → review → transaction → assets + usage/disks/RAM + audit.

## 6. ثبت مرحله‌ای

صفحه `asset_wizard.php` مراحل را با ترتیب زیر ارائه می‌کند:

1. کامپیوتر
2. چاپگر
3. اسکنر
4. نمایشگر
5. تأیید نهایی

در مرحله تحلیل کامپیوتر، `MonitorDetails` به داده نمایشگر و اطلاعات چاپگر/اسکنر مرتبط به رکوردهای مراحل بعدی کپی می‌شود. قبل از تأیید نهایی هیچ تجهیزی insert نهایی نمی‌شود.

در پایان، ثبت چهار تجهیز داخل یک transaction انجام می‌شود؛ در صورت خطا rollback انجام می‌شود.

## 7. اصل تراکنش

در مرحله نهایی:

- شماره اموال هر چهار مرحله بررسی می‌شود.
- تکرار بین مراحل بررسی می‌شود.
- تکرار با DB بررسی می‌شود.
- transaction شروع می‌شود.
- assetها و داده‌های وابسته درج می‌شوند.
- audit ثبت می‌شود.
- commit انجام می‌شود.

هر خطای میانی باید rollback کند.

## 8. Active Directory

کلاس `app/Services/ActiveDirectory.php` مسئول:

- اتصال LDAP/LDAPS
- bind
- جستجوی کاربران
- استخراج employeeID/sAMAccountName
- استخراج displayName/department/title
- upsert در personnel

رمز Bind در DB به‌صورت encrypted ذخیره می‌شود.

## 9. اصل جداسازی تجهیزات

`MonitorDetails` نباید به‌عنوان peripheral کامپیوتر ثبت شود؛ اطلاعات نمایشگر باید در asset نوع display قرار گیرد.

اطلاعات چاپگر و اسکنر نیز در asset نوع مربوطه قرار می‌گیرد.

## 10. قابلیت ادامه توسعه

توسعه‌دهنده جدید نباید منطق business را به‌صورت پراکنده در HTML تکرار کند. قبل از تغییر:

- مسیر request را پیدا کند.
- جدول مقصد را پیدا کند.
- permission مربوط را بررسی کند.
- audit را در نظر بگیرد.
- تست syntax و smoke test را اجرا کند.
- مستندات مرتبط را به‌روزرسانی کند.
