# 02 — شرح خدمات و فرایندهای سامانه

## 1. بازیگران

### مدیر

مدیر می‌تواند:

- کاربران را ایجاد/ویرایش/فعال/غیرفعال کند.
- نقش کاربر را تعیین کند.
- دسترسی create/edit هر نوع تجهیز را تعیین کند.
- تنظیم Active Directory را مدیریت کند.
- اتصال AD را تست کند.
- پرسنل را sync کند.
- تجهیزات را مدیریت کند.
- رویدادها و گزارش‌ها را مشاهده کند.

### برداشت‌کننده

برای جمع‌آوری اطلاعات تجهیزات استفاده می‌شود. دسترسی او به هر چهار پایگاه می‌تواند مستقل تنظیم شود.

### کارشناس

مانند برداشت‌کننده از permissionهای نوع تجهیز استفاده می‌کند و برای ثبت/اصلاح داده‌های فنی قابل استفاده است.

### مشاهده‌کننده

برای مشاهده، جستجو و گزارش‌گیری است و نباید عملیات ویرایش تجهیزات انجام دهد.

## 2. ورود

1. کاربر صفحه login را باز می‌کند.
2. session احراز هویت می‌شود.
3. role در session قرار می‌گیرد.
4. صفحات محافظت‌شده `require_login()` یا `require_role()` را اجرا می‌کنند.
5. عملیات حساس CSRF token دارند.

## 3. آماده‌سازی پرسنل

1. مدیر وارد Active Directory می‌شود.
2. host، port، Base DN، Bind user، password و filter را تنظیم می‌کند.
3. تنظیمات ذخیره می‌شود.
4. «تست اتصال» اجرا می‌شود.
5. پس از موفقیت، sync انجام می‌شود.
6. پرسنل در جدول `personnel` ذخیره/به‌روزرسانی می‌شوند.
7. هنگام ثبت کامپیوتر، مسئول از همین فهرست انتخاب می‌شود.

## 4. ثبت تجهیزات

مسیر اصلی ثبت مرحله‌ای `asset_wizard.php` است.

### مرحله A — کامپیوتر

- CSV خوانده می‌شود.
- delimiter تشخیص داده می‌شود.
- BOM حذف می‌شود.
- مقادیر pipe-separated نرمال می‌شوند.
- مشخصات کامپیوتر نمایش داده می‌شود.
- شماره اموال ۷ رقمی دریافت می‌شود.
- مکان دریافت می‌شود.
- پرسنل برای کامپیوتر قابل انتخاب است.
- RAM و Disk ساختاری استخراج می‌شوند.
- شاخص‌های usage و CollectedAt نمایش داده می‌شوند.

### مرحله B — چاپگر

اطلاعات چاپگر در رکورد مستقل printer تکمیل می‌شود. MAC از CSV برای printer/scanner حذف می‌شود و IP در فرم قابل ورود است.

### مرحله C — اسکنر

اطلاعات اختصاصی اسکنر ثبت می‌شود و IP در صورت نیاز به‌صورت دستی ثبت می‌شود.

### مرحله D — نمایشگر

`MonitorDetails` و فیلدهای نمایشگر در asset نوع display قرار می‌گیرند.

### مرحله E — مرور و تأیید

کاربر خلاصه هر چهار تجهیز را می‌بیند. ثبت نهایی فقط با دکمه تأیید انجام می‌شود.

## 5. کنترل شماره اموال

دو سطح کنترل وجود دارد:

- کنترل لحظه‌ای AJAX از `asset_check.php`
- کنترل قطعی سمت سرور در مرحله next و دوباره در finish

اگر شماره قبلاً وجود داشته باشد، لینک ویرایش همان تجهیز ارائه می‌شود.

## 6. ثبت نهایی و سابقه

در زمان ثبت:

- user id ثبت‌کننده در `created_by/updated_by`
- IP ثبت‌کننده در `registration_ip`
- زمان ثبت در `registration_at`
- زمان برداشت داده سخت‌افزار در `usage_stats.collected_at`
- رویداد کامل در `audit_logs`

ثبت این موارد دو مفهوم زمانی را از هم جدا می‌کند:

**CollectedAt** = زمانی که ابزار/CSV اطلاعات سخت‌افزار را جمع‌آوری کرده است.

**registration_at** = زمانی که کاربر سامانه اطلاعات را در DB ثبت نهایی کرده است.

## 7. ویرایش تجهیز

ویرایش باید با asset type و permission کاربر کنترل شود. تغییرات مهم باید audit شوند.

برای کامپیوتر، Disk و RAM موجودیت‌های وابسته‌اند و نباید فقط به JSON فشرده شوند.

## 8. جستجو و گزارش

لیست تجهیزات باید قابلیت:

- تفکیک نوع تجهیز
- جستجو
- فیلتر
- pagination

داشته باشد. پرسنل نیز جستجو و pagination دارد.

## 9. خطاها

خطای اعتبارسنجی باید قبل از transaction نهایی اعلام شود.

خطای DB در transaction باید rollback کند.

خطای AD باید به کاربر پیام قابل فهم بدهد و رمز Bind را نمایش ندهد.

## 10. فرایند مطلوب در عملیات واقعی

ترتیب پیشنهادی عملیاتی:

AD sync → ثبت/تحلیل CSV → تکمیل چهار مرحله → review → final approval → گزارش/کنترل audit.
