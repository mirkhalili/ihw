# 10 — قرارداد تغییرات و نسخه‌بندی

## نسخه‌بندی

پروژه از نسخه چهاررقمی استفاده می‌کند:

`MAJOR.MINOR.PATCH.BUILD`

نمونه:

`1.0.0.3`

هر release/commit مهم باید نسخه را در فایل `VERSION` مشخص کند.

## قواعد پیشنهادی

- MAJOR: تغییر ناسازگار اساسی
- MINOR: قابلیت جدید با حفظ قرارداد قبلی
- PATCH: اصلاح رفتار/bug
- BUILD: مرحله توسعه، تست یا بسته تحویلی

## گزارش تغییر

برای هر نسخه:

### Added
قابلیت‌های جدید

### Changed
رفتارهای تغییرکرده

### Fixed
اشکالات رفع‌شده

### Database
migrationهای اضافه/اجراشده

### Tests
تست‌های اجراشده و نتیجه

### Deployment
نکات لازم برای سرور

## نسخه فعلی مستندات

**1.0.0.3**

این نسخه مستندات برای انتقال دانش کامل پروژه اضافه شده است.
